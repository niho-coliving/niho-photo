# NIHO 6 の JPEG / PNG 現像式（#18397）

`niho-6` は JPEG / PNG の原本と非 RAW 作業コピー（HEIC などから作るもの）の式です。`niho-2` との違いは次の 3 つだけです。保存済みの `niho-1` / `niho-2` の補正は変えません（spec 決まりごと 4）。独立評価が JPEG 用の gate を通った（R26）ので、新しい JPEG / PNG / 非 RAW 作業コピーの編集の既定は `niho-6` です（旧 RAW の新規編集は `niho-2` のまま。読み手と既定の決めごとは spec の「niho-6 の product reader / producer」）。

1. ハイライト（0 以下）とシャドウ（0 以上）を、Lightroom の JPEG の書き出しから学習した応答で描く。応答は**露出を当てた後の写真**で決める（R20）。
2. Vibrance と HSL の輝度を RAW の凍結した応答（NIHO 3 の Vibrance・NIHO 4 の HSL の輝度）で描く（R14）。
3. 正の Blacks を RAW の曲線（NIHO 3）で描く（R18）。

名前: 最初は `niho-5`（仮）だったが、P5（#18445）が `niho-5` を signed RAW の明部の式に使ったので `niho-6` に改めた（2026-10-15）。

## 現在地（2026-10-15）
- **凍結した候補**（2026-10-16）: 26 特徴・8/4 の網、教師 57 場面（2 束）で単独の操作とプリセットの文脈を同時に学習（R23）、`highlightAlpha` 0.7、露出を当てた後の特徴（R20）、今の式の局所の H/S を `LEGACY_SHARE` 0.5 残す（R24）。Vibrance・HSL の輝度・正の Blacks は RAW の応答（R14・R18）。

## 原因（paneB-11・round3・round10、gate の測り方）

gate と同じ測り方（長辺 1500・blur 2・平坦画素）で、今の JPEG の経路（`niho-2`、2048px の一発の描画）を Lightroom と比べた。

| 操作（8 場面） | 平均 ΔE00 | p99 の平均 | p99 の最大 |
|---|---:|---:|---:|
| 中立 | 0.10 | 0.49 | 0.88 |
| 露出 +1 / −1 EV | 0.76 / 0.65 | 2.45 / 1.63 | 3.23 |
| 増分 WB 暖 / 寒 | 0.41 / 0.48 | 1.40 / 1.55 | 1.77 |
| HSL 青 / 橙 | 0.39 / 0.50 | 1.36 / 1.75 | 2.18 |
| ハイライト −50 / −100 | 1.21 / 2.35 | 5.78 / 12.28 | 18.31 / 38.92 |
| シャドウ +50 / +100 | 0.96 / 2.05 | 3.69 / 7.80 | 6.37 / 12.63 |

- 外れるのはハイライト／シャドウだけ。差の大半は明るさで、色だけの差は p99 で 2〜5（夜の 1 場面を除く）。
- Lightroom の JPEG のハイライトは、**写真の平均 log 輝度に対する明るさ**で効きが決まる（場面間のばらつき 0.08 EV。絶対の明るさで見ると 0.42 EV）。暗い夜の写真の一番明るい所は −100 で −3.4 EV 下がり、明るい写真では −0.3〜−0.4 EV。シャドウは **p90 に対する暗さ**で決まる（0.21 EV。絶対なら 0.46 EV）。今の式（Photo Bench 由来の固定の曲線と写真全体の係数 1 つ）はこの適応が弱い。
- 色: ハイライトを下げると Lightroom は明部の彩度を保つ（色差 `rgb − Y` の倍率が輝度の倍率の約 0.3〜0.5 乗）。シャドウは約 1.05 乗。今の式は 1 乗（彩度が落ちる）。
- RAW の学習済み応答（`niho-3` / `niho-4`）は使わない。sRGB には headroom が無く（白飛びの上の値が無い）、教師の領域（表示用に階調を付けた後の値）も違う。同じ形の式を JPEG の教師で学習し直す。

## 式

- 解析: 写真全体（切り抜き・プレビュー・見本でも原本全体）を、元の色空間のまま面積平均で長辺 750 にし、linear ProPhoto にする。26 特徴は RAW と同じ凍結の定義（`raw_response::feature_vectors`。σ1 のぼかしの後）。
- 応答: ハイライトとシャドウに 1 つずつ、特徴の部分集合 → tanh → tanh → softplus の網で画素ごとに `a, b ≥ 0`。gain（EV）はハイライト `−(h·a + h²·b)`（`h = −H/100`、上限 8 EV）、シャドウ `s·a + s²·b`（`s = S/100`、上限 4 EV）。
- 当て方: gain を準備する画像の大きさへ双線形で戻し、画素ごとに `out = rgb·G + (rgb − Y)·(C − G)`、`G = 2^(gH + gS)`、`C = 2^(αH·gH + αS·gS)`（`Y` は ProPhoto の輝度。linear sRGB の原本では同じ輝度を sRGB の係数で計算する）。
- 順序: 準備した画像に `niho-2` の描画（露出・コントラスト・白・黒・カーブ・自然な彩度・彩度・HSL・カラーグレーディング・増分 WB の LUT・効果）。局所階調はハイライトの正・シャドウの負の向きとテクスチャ・明瞭度だけを従来の式で行う。
- 互換: H/S が 0、または逆向きだけの設定は `niho-2` とバイト一致（`tests/niho6.rs`）。RAW の作業コピーと camera-linear は `incompatible_working_copy` で拒否。プリセットを当てても `niho-6` のまま、XMP の書き出しは `niho-2` と同じ（増分 WB は Custom＋Incremental）。

係数の表現は `crates/niho-develop/niho6/response-jpeg.json`（`niho.jpeg-response-models.v1`）。学習は crate の外（`tools/calibrate/fit_niho6_response.py`）で、crate の中では学習も閾値の選択もしない。係数の出どころは `niho6_response.rs` の SHA-256 で固定する。

## 教師・凍結・独立評価の手順

1. 教師: `tools/calibrate/make_lr_p3_jpeg.py --set teachers`。35 場面（iPhone 13 Pro 12・iPhone 11 8（HEIC と JPEG）・カメラ JPEG 7・round3 の 8）× 22 設定（中立、ハイライト −30/−60/−100、シャドウ +30/+60/+100、その組 2 つ、白 −50、黒 +80、コントラスト −40、自然な彩度 +40、彩度 +40、HSL、テクスチャ +40、同梱プリセット 3 本と H/S を 0 にした 3 本）。HEIC は製品と同じ `apple-raw-linear raster` で JPEG にする。レンズ補正は全部オフ。
2. 選び方: 撮影日・機種・ISO・Software だけで決める（画素を見ない）。1 撮影日 1 枚、ISO で明・中・暗を混ぜる。独立評価を先に選び、教師と撮影日を重ねない。選定 `selection.json` の SHA-256 は Issue に記録した。
3. 学習: `fit_niho6_response.py dataset`（特徴は crate の `examples/niho6_features.rs` から）→ `fit --folds dates`（撮影日ごとに分けた検証で特徴の部分集合と網の大きさを決める）→ `export`。
4. 凍結: 係数の SHA-256・seat の commit・描画に使った binary の SHA-256 を `freeze.json` に記録してから、独立評価の書き出しを開く。凍結の後に係数・閾値・場面を変えない。
5. 独立評価（1 回だけ）: 中立と同梱プリセット 3 本を製品と同じ経路（`xmp::apply_preset` を `niho-6` の新しい編集に当てる、2048px の一発の描画）で描き、凍結した JPEG 用の gate（上の決めごと: 中立の平均 ≤ 2・各プリセットの平均 ≤ 3・場面×プリセットの p99 > 8 は全体の 15% 以下・どの場面×プリセットも今の式〔niho-2〕より p99 が 2 以上悪化しない。長辺 1500・blur 2・平坦画素）で判定する。全件 p99 ≤ 8 は RAW の gate で、JPEG には当てない。
