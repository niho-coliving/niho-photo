# V2 最初の区切り：色ノイズとデモザイク

2026-09-30、Mac Studio。比較は DC-S5 ISO1600 と ZV-E10M2 ISO2000 の実写 RAW 各1場面、長辺2560、Apple 標準NR・レンズ補正OFF。NIHO 側は現在の DCP と線形 ProPhoto PNG16。私物写真は repository に含めない。

| Apple 標準NR | 1.00 / 1.00 | 1.00 / 1.00 | 参照 |

## Rust の色ノイズ処理と追加高ISO場面（続行後）

初期 Python 試作より単純な線形輝度ガイドに変更して実験用 crate へ移した。長辺2560、Apple 標準NR、レンズ補正OFF、同じ DCP/校正、上記と同じ平坦タイル指標。輝度を代数的に保持し、強い色境界は元の色差に混ぜ戻す。ISO 2500 以上では半径と境界マスクを広げる暫定設定。数値が Apple より小さすぎる場面は過剰な平滑化の可能性があり、目視判定が必要。

| カメラ / ISO / 場面数 | 色ノイズ Apple=1: 処理前 → Rust処理後 | 輝度ノイズ Apple=1: 処理後 | Rust処理後の合計時間 |
| --- | --- | --- | --- |
| DC-S5 / 1600 / 1 | 30.81 → 0.92 | 1.86 | 988ms |
| ZV-E10M2 / 2000 / 1 | 27.33 → 0.82 | 1.97 | 921ms |
| DC-S5 / 3200 / 4 | 3.29〜3.65 → 0.018〜0.024 | 1.42〜1.63 | 1222〜1258ms |
| ZV-E10M2 / 2500 / 1 | 49.87 → 0.49 | 1.85 | 1146ms |
| ZV-E10M2 / 3200 / 1 | 90.77 → 1.14 | 1.92 | 1154ms |
| DC-S5 / 6400 / 5 | 7.47〜228.49 → 0.195〜1.787 | 1.16〜3.09 | 1187〜1293ms |
| ZV-E10M2 / 6400 / 1 | 66.91 → 0.50 | 1.98 | 1124ms |

ISO1600〜3200の追加場面は平坦部の色ノイズ**数値だけ**なら暫定1.5倍基準に入った。ISO6400の DC-S5 は5枚中1枚が1.79で超過。輝度ノイズは残る。写真の細部や肌の色を数値で判定していない。初期設定の Rust 部分は約0.7〜1.0秒の増分であり、wasm/browser の時間・メモリは未測定。ISO適応値はこの追加場面で選んだため、独立試料による検証も必要。

## Lightroom 中立との色（round6 17場面）

DC-S5 13場面、ZV-E10M2 4場面の RAW と Lightroom 中立の書き出しを私的な領域で測った。既存 `crates/niho-base-raw/tools/colorcheck/measure.py` の `per-image-rgb-tone-curve`、長辺1500、同一場面の camera RGB clip mask を使用。両候補に同じ DCP を適用し、色ノイズ処理以外は同条件。ΔE00 は場面を等重みで平均した値。高ISO追加12場面には Lightroom 中立の書き出しが無いため、この表に入れていない。

| カメラ | 場面数 | ΔE00平均 bilinear → Rust色NR | p99 bilinear → Rust色NR | 彩度比 bilinear → Rust色NR |
| --- | ---: | ---: | ---: | ---: |
| DC-S5 | 13 | 1.40 → **1.26** | 5.41 → 4.96 | 0.994 → 0.986 |
| ZV-E10M2 | 4 | 1.87 → **1.41** | 7.23 → 6.44 | 0.979 → 0.969 |

17場面すべてで平均色差が下がり、平均2.0以下の暫定基準は両機種で満たした。彩度は少し下がる。細部の色、肌の質感はこの指標では合格にできない。

Sony DSC09188 のオレンジ色の服の輪郭1か所を、レンズ補正後の同じ画素列77本で点検した。色境界の10–90%遷移幅は Apple 3.80px、NIHO レンズ補正のみ3.73px、色NR＋レンズ補正3.79px。ここでは色NRによる輪郭幅の増加は見られないが、1か所の測定を全場面の細部判定に広げない。

## 埋め込みレンズ補正（実験用 Rust crate）

Sony ARW の SubIFD 歪み・周辺減光係数と、Panasonic RW2 `0x0119` の歪み係数を直接読んで、長辺2560の線形画像を補正した。Apple のレンズ補正ありの出力を幾何参照にし、`tools/lens-check/lens_geom.py` で相似変換後の局所ずれを測定。画質の基準は Apple 標準NRではなく NRなし、レンズ補正前後だけを比較した。パナソニックの半径の7次式は [RW2解析の原資料](https://syscall.eu/archive.html#pana) を出発点に、DC-S5の2種類のレンズで確認した。

| カメラ / レンズ | 補正前 RMS / 周辺平均 | Rust補正後 RMS / 周辺平均 | Rust補正の増分 |
| --- | ---: | ---: | ---: |
| ZV-E10M2 / E PZ 16mm | 13.3px / 算出不可（有効タイル不足、最大40.0px） | **0.0px / 0.1px** | 319ms |
| DC-S5 / Sigma 50mm | 8.2px / 17.6px | **0.1px / 0.1px** | 701〜744ms |
| DC-S5 / LUMIX 20–60mm（26mm） | 12.5px / 24.1px | **0.1px / 0.2px** | 706ms |

Sony補正後の周辺光量は、同じ場面のApple補正画像と中心比で最大0.01EVの差だった。幾何の暫定基準（周辺平均2px、周辺減光±0.1EV）を上記の試料では満たした。Panasonicの周辺減光と倍率色収差は試作対象外。歪み係数を読めないレンズ・RAWでの挙動も一般化しない。

## ハイライトの失敗例

`--highlight preserve-wb` を切替として加えた。センサー値の飽和は1で止めるが、白バランスを掛けた後の1超をデモザイク・色変換へ残す、単純な headroom 保持である。DC-S5の12場面でApple NRなしと比較し、元の出力が最大チャンネル0.98超かつAppleの線形輝度0.35〜0.92の画素を使った。50画素以上あった11場面のうち8場面で、Appleとの log(R/G), log(B/G) の中央値が悪化した。窓際・肌の P1581387 は 0.107 → **0.250**、別の P1570280 は 0.150 → 0.115 で、改善は場面に依存した。P1581387 の窓には目立つ偽色が出たため、`clip` を既定のままにする。飽和した色を再構成できるという結論には至っていない。

## 処理時間と判断

24〜26MP RAW のネイティブ単回測定（Mac Studio、長辺2560）。`/usr/bin/time -l` のピークRSSは画像・RAWを含むプロセス全体で、V1の wasm 線形メモリとは測定対象が違う。

| カメラ | bilinear 基本 | 色NR＋レンズ補正 | ピークRSS 基本 → 追加後 |
| --- | ---: | ---: | ---: |
| ZV-E10M2 | 212ms | 1300ms（色NR775、レンズ319） | 638 → 888MiB |
| DC-S5 | 337ms | 2041ms（色NR988、レンズ701） | 630 → 875MiB |

**暫定結論**: 両機種とも色・ISO1600〜3200の平坦部色ノイズ・試したレンズの幾何は数値基準に入る。一方、ハイライト復元は未達で、輝度ノイズ・ISO6400の一部・細部の見え方が残る。したがって **DC-S5 / ZV-E10M2 とも、現時点で自前デコードを既定へ切り替える判断はしない。Mac の Apple 現像を維持する**。高ISOページの owner 目視判断と、実際のブラウザで追加処理を使ったときの時間・メモリは未了。V1で成立したブラウザの基本デコード結果を、新しい品質処理の性能保証として扱わない。
