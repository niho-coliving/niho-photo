# 公開ゲート

## 適用範囲

`niho-photo` の全コミット、PR、CI artifact に適用する。非公開 `niho-clients` / `niho-app` の Git 履歴は取り込まず、許可したファイルを新しいコミットとして移す。公開 PR に置いた内容はマージ前でも外部から読めるため、push 前に同じ判定を行う。

## 判定と証拠

| 判定 | 条件 | 処理 |
| --- | --- | --- |
| 公開可能 | NIHO の権利または再配布を認めるライセンス、出所、必要な表示、機密性、用途をファイル単位で確認済み | allowlist に登録し、hash と承認者を記録してから移植 |
| 要置換 | 機能・テストには必要だが、実データや権利未確認資産を含む | 合成 fixture、NIHO が作成した代替物、公開 interface に置き換える。元ファイルは持ち込まない |
| 非公開維持 | 本番権限、個人情報、内部運用、配布できない第三者資産、出所不明の素材 | 公開 repo、PR、ログ、artifact へ入れない。必要なら非公開側で保持 |

「gitleaks の誤検知」は公開許可を意味しない。検出ごとに原本の利用箇所と型を確認し、secret の真偽と資産の権利を別々に判定する。広域の除外設定を追加しない。真の secret は公開前に失効・再発行し、値や復旧手順を公開記録に書かない。オーナーが自作・撮影・公開許可を確認した資産も、埋め込み ICC・EXIF と第三者由来データを別に検査する。

## 公開禁止

- API・DB・認可の最終実装、内部運用・予算・private remote / package / runner 情報
- 本番 token、client secret、Apple 署名・公証・updater の資格情報、秘密鍵、証明書
- 個人情報、実利用ログ、ユーザーの写真・RAW・音声・位置情報・EXIF
- 権利確認前のアイコン、フォント、画像、カラープロファイル、モデル、校正入力・派生値
- 署名済み成果物、本番配布用の権限付き workflow

機械検査の初期設定は [publication-policy.json](publication-policy.json) に置く。禁止パス・拡張子・サイズ上限と、資産に allowlist manifest を求める契約を定義した。公開候補の fixture は出所と公開許可を記録する。RAW や比較画像が必要な検証は、権利を確認できるデータを別途用意するまで公開 CI の必須条件にしない。

## PR を通す条件

1. 移行 manifest の明示パスだけを新規コミットへ追加し、移行元の完全 commit SHA、各ファイルの SHA-256、権利根拠を記録する。submodule、private remote、親 commit の移植は禁止。
2. 差分と全公開履歴に secret scan を実行する。検出を単に ignore せず、個別監査記録を更新する。
3. 実データ・禁止パス・巨大な binary・未登録資産を publication guard で拒否する。`pull_request` では read-only 権限、GitHub-hosted runner、secret なしを使う。
4. コード・依存物のライセンスと notice、資産の出所と再配布条件、生成物への混入を確認する。判断不能なら非公開維持または置換する。
5. 公開前の安全・権利レビューを記録し、レビュー対象の exact commit を固定する。レビュー後に差分が増えたら再走査する。

公開 CI は署名・公証・本番配布を起動しない。CI が通っても配布の承認にはならない。

## 報告と記録

公開 Issue・PR には検出件数、分類、影響範囲、修正 commit だけを書く。secret の値、検出行の原文、private URL、実画像やログを貼らない。脆弱性は公開 Issue にせず、`SECURITY.md` の非公開窓口を使う。監査の元レポートは非公開環境で保持し、公開側には値を除いた [検出台帳](gitleaks-findings.csv) だけ置く。
